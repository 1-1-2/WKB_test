## 2. 一致性口径（执行前对照）

| 项 | 官方行为（规格） | 本项目实现 |
|---|---|---|
| 拓扑 | 手机 = TCP server 8125 + UDP sender（connect 到 PC 媒体端口）；PC = TCP client + UDP receiver | 同 |
| TCP 帧 | `[type u8][len u32 大端][payload]` | 同 |
| 101 hello | PC 发 `65 00000006 04 06 03 00 00 00`；手机应答 `[status u8][4 u8]` | 同 |
| 102 参数 | `codec=2(Opus) rateIdx=2(48000) mediaPort u32 BE`；应答 1B 状态 | 同 |
| 103 / 104 / 105 | 开始 / 停止 / 心跳（约 1s，无应答）；手机 5s 无心跳强制断链 | 同 |
| 104 应答怪癖 | 官方 app 实际回 type **102** 帧 `66 00000001 00` | 已复刻 |
| UDP 媒体 | 格式 C 头 11B：`04 00` + `len u16` + `seq u16` + `ts u32` + `vol u8` + 单包 Opus | 同 |
| 音频参数 | 20ms 帧、48kHz 单声道、Opus | 同（64kbps） |
| 音量字段 | 默认 5（单位增益） | 同（UI 可调 0–255，默认 5） |

## 3. 人工互操作清单

> 前置：手机与 PC 接入**同一局域网**；确认 PC 防火墙未拦截 TCP 8125 与入站 UDP 媒体端口。
> 判"通过"的标准：PC 端录音应用（录音机 / OBS）能采到手机端声音，无声但结构对 / 无声且无报错 /
> 断续 / 连不上，分别记入备注。

### A 组：官方 Android app → miclink Windows 客户端

验证"我们的 PC 端能被官方手机端驱动"。

| # | 步骤 | 预期 |
|---|---|---|
| A1 | PC 启动 miclink Windows 客户端，进入连接界面 | 出现地址/端口输入项 |
| A2 | 手机启动**官方** WOMic app，授予麦克风权限，启动服务 | 状态显示"等待 PC 连接"，显示手机地址（形如 `192.168.x.x:8125`） |
| A3 | PC 端填入 A2 的手机地址，发起连接 | TCP 握手成功；app 状态变为已连接 |
| A4 | PC 端点"开始推流"；对手机说话 | PC 端 UDP 开始收包；PC 录音应用采到人声 |
| A5 | 持续 60s，观察电平/统计 | 无断链（PC 端约 1s 发一次 105 心跳，官方 app 5s 看门狗不触发） |
| A6 | PC 端点"停止" | app 停止采集；TCP 连接按官方清理流程关闭 |
| A7 | PC 端直接断开（杀进程/断网） | app 在约 5s 内看门狗断链，状态回落 |
| A8 | 重复 A3–A6 三轮 | 三轮全部成功（重连稳定性） |

### B 组：miclink Android app → 官方 Windows Client 6.3

验证"我们的手机端能驱动官方 PC 端"。

| # | 步骤 | 预期 |
|---|---|---|
| B1 | PC 安装并启动官方 `WOMicClient.exe`（6.3） | 主界面出现 |
| B2 | 手机安装本仓库构建的 APK，授予麦克风/通知权限，点"启动服务" | 状态变为"等待 PC 连接"，状态卡显示手机地址 |
| B3 | 官方客户端 `Connection > Connect...`，选 **Wi-Fi**，主机填 B2 的手机地址，Connect | 连接成功（官方客户端识别协议版本与参数） |
| B4 | 官方客户端点开始推流；对手机说话 | 官方客户端收到 Opus 流并灌入 `womic.sys`；系统录音设备（WO Mic Device）采到人声 |
| B5 | 持续 60s | 无断链（心跳周期匹配官方 5s 看门狗） |
| B6 | 官方客户端停止推流 / 断开 | 本 app 停止采集，状态回落 |
| B7 | 重复 B3–B6 三轮 | 三轮全部成功 |
| B8 | 调试音交叉验证：本 app 打开"调试音"开关（440Hz 正弦），重跑 B3–B4 | PC 端采到 440Hz 纯净正弦（判频可用 Goertzel） |

## 4. 已知限制（执行前知晓）

1. **必须人工**：官方两端（Qt 客户端 / 官方 app）均无法脚本化驱动
   （历史结论：消息类注入只改 UI 状态不改内部状态；Procmon 实证官方客户端对
   `\\.\WOMic` 的调用只能观察不能重放）。本清单不接受自动化替代。
2. **官方 PC 客户端默认媒体端口疑为 8126，未经 trace 实证**（协议规格 T1 待实测项）；
   若 B4 无声，先核对官方客户端实际协商/使用的 UDP 端口。
3. **PC 防火墙**：官方客户端首次推流时入站 UDP 媒体端口可能被拦截（T5 待实测）；
   无声时先临时放行再定位。
4. **采样率**：官方 app 在设备不支持 48kHz 时会回退 44.1k 并重采样；本 app 锁定 48000，
   不支持则报错。两侧行为不同但都合规（驱动只搬字节，PC 端解码侧统一）。
5. **Speex / 头格式 A/B**：本项目不支持（codec 100 回 status=12，只用格式 C）；
   与官方 6.3 默认参数（Opus + 格式 C）兼容，但旧版官方客户端不在互操作范围内。
6. **音量**：官方默认 5（单位增益）；本 app 默认 5，调试时如无声先确认未被调成 0。

## 6. 失败速查（无声时按序排查）

| 现象 | 优先怀疑 |
|---|---|
| 连不上（TCP） | 不在同一网段；PC 填错手机地址；防火墙拦 TCP 8125 |
| 连上约 5s 即断 | PC 端未按 ~1s 发 105 心跳（自写 PC 端最易漏） |
| 参数错误（status 12/13） | 102 报文 codec/rateIdx 非法 |
| 有数据没声音 | PC 媒体端口 UDP 被防火墙拦；音量字段为 0；PC 端默认输出设备选错 |
| 声音断续 | 换 5G Wi-Fi / 有线；检查 UDP 链路抖动缓冲与丢包 |
